# Bob reference

[Back to the overview](../README.md). Commands below run from the repository root.

A native macOS developer workspace with an agent harness written in Swift. SwiftUI and AppKit provide the interface; native WebKit renders project web pages. Foundation, Security, CryptoKit, and Network provide the runtime. The app has no third-party package dependencies. Claude subscription chats use the installed, unmodified Claude Code binary; direct API providers use the Swift agent runtime. The optional local decision worker uses MLX Swift for Metal acceleration.

## Run

Requires macOS 14 or later and Xcode's Swift toolchain.

```sh
make run
```

This builds an ad-hoc signed app at `.build/Bob.app` and opens the current project. Open `Package.swift` in Xcode to develop the app. `make release` produces an optimized build; `make test` runs the native tests.

With Xcode 26 and an iOS runtime installed, `bash scripts/test-simulator.sh` builds a small fixture app, creates a temporary iPhone, tests live display, taps, drags, typing, Home, and native view cleanup, then deletes the temporary device. Ordinary test runs skip the live simulator test.

## Connections

Open **Settings & connections** (`⌘,`). Direct API requests go from Bob to the selected provider. Claude subscription requests go through your installed Claude Code runtime.

- **ChatGPT:** Continue with ChatGPT opens OpenAI's official browser authorization flow. Bob implements dynamic client registration, PKCE, state and nonce validation, signature-verified identity tokens, account selection, rotating refresh tokens, and revocation in Swift. Select an account, load its model catalog, and choose a model. This uses OpenAI's documented ChatGPT plan-sharing flow; access depends on the account's granted permissions and available models.
- **OpenAI API:** Save an API key, then enter or load a Responses API model ID. API billing is separate from a ChatGPT subscription.
- **Claude:** Install Claude Code, then choose Continue with Claude in Settings. The official binary handles browser sign-in and credential storage; an existing Claude Code subscription login is detected automatically. If the browser shows a sign-in code, paste it into the sign-in terminal in Settings. Bob loads the installed runtime’s models and supported effort levels. The native interface, Clef tool reviews, host shell execution, checkpoints, and browser/desktop tools stay in Bob.
- **Claude API:** The separate Anthropic API-key connection remains available for API-billed chats.
- **OpenAI-compatible:** Configure an API base URL including its prefix (for example, `http://localhost:11434/v1`), an optional key, and a model ID. The server must support streamed Chat Completions and function tools for agent operations. HTTPS is required except on loopback.

Secrets are stored in Bob's macOS Keychain items. Conversations, provider settings without secrets, and file checkpoints are stored in `~/Library/Application Support/Bob/`. ChatGPT account registration labels are stored in app preferences. Bob does not import another application's subscription credentials.

The bottom-right **Usage** panel shows the selected chat's model, effort, and cumulative input/output tokens. For ChatGPT plan chats, it also reads real account limits through the installed Codex client's documented `account/read` and `account/rateLimits/read` RPCs. The local Codex account must match Bob's selected account's email; a mismatch stops the quota request. Reported windows show the percentage remaining and reset time, refresh on opening and every minute while open, and support manual refresh. Missing limits stay unknown and passed resets require a new sample. These are the local Codex sign-in's account limits; its selected workspace and Bob's app allowance can differ. Bob's app-specific allowance is managed separately in the linked Usage settings. This connection only reads account status; it does not run chats, change sign-ins, or export credentials. See the [account-status protocol](https://learn.chatgpt.com/docs/app-server#6-rate-limits-chatgpt).

New chats automatically receive a short, descriptive title from their first message using the selected model. A compact prompt preview appears immediately while the title is generated in the background. Titles persist across restarts and stay stable through follow-ups. Failed or cancelled title requests keep the preview without interrupting the chat. Claude subscription titles use a separate tool-free session that is not saved or resumed.

Messages sent while a chat is working are routed by local Clef: corrections, constraints, and changes steer the current task; independent or explicitly subsequent tasks queue until it finishes. Return, `⌘Return`, and the send control submit the update for routing. If Clef is unavailable or routing fails, messages steer as before. Earlier queued messages are delivered first if a later update steers, preserving submission order. Stop preserves undelivered messages in conversation history. Bob interrupts stale model generation and pending reviews/approvals, lets an executing tool finish once, skips remaining old proposals, and continues with the new instructions in order. Claude uses its interrupt control and streaming input within the same process and session. Stop remains a separate control; other chats keep running. Original steering messages are retained for safety authorization and recovery.

Live ChatGPT inference was verified on October 16, 2026 with the connected account: a model called the native project-file listing tool, received its result, and returned a visible answer. Retrying an unfinished sign-in reuses its registration; **Use a different account** starts a new registration so it can select another account or workspace. No API-key-billed request has been tested.

## Local decisions

On Apple Silicon with macOS 15+, install the optional Clef-flash worker:

```sh
make decisions
make build
```

The initial setup downloads approximately 5.3 GB of pinned, SHA-256-verified weights and compiles a separate Swift/MLX worker and its Metal shaders. Xcode's Metal Toolchain component must be installed (`xcodebuild -downloadComponent MetalToolchain`). Setup is resumable. Model files stay in `.build/decisions/model`; building the app records that local path and embeds the worker. Moving the project requires rebuilding the app. Normal app builds do not download weights or build MLX. The chat UI still builds on macOS 14; executing agent tools now requires Clef and macOS 15+ for safety review.

Clef-flash is Cloudflare's 9B decision model, here using the text-only affine 4-bit [Swift-compatible export](https://huggingface.co/aufklarer/Clef-flash-9B-MLX-4bit/tree/92a850bc10a355a69799e63fe87aa7545c551c74) and a pinned [native Swift implementation](https://github.com/soniqo/speech-swift/tree/1aed9dfa57f900eb6ffd6671246f4712819a0e75/Sources/Clef). It scores allowed answers in one forward pass through the backbone and joint decision head. It accepts text or JSON rendered as text; this integration does not accept images or video. It is a decision service, separate from the chat model picker.

After reopening the built app, the agent has a `local_decide` tool for choice, boolean (`noul`), and ordered score questions. Native features can also call `BobCore.LocalDecisionModel.decide(DecisionRequest)` directly. Calls run serially in a background worker shared across project windows, retain the loaded model between requests, and unload it after 60 seconds idle. Cancellation and a 120-second execution deadline stop the worker. The default input limit is 4096 tokens, configurable up to 16384; oversized input fails without truncation.

Results include per-option probabilities, selected options, token count, model-load time, and decision time. For boolean questions, `noul` is the probability of true; `confidence` is the probability of whichever option won. Scores are expected zero-based level indices. Probabilities do not grant permission to perform actions; existing tool approvals still apply. The decision worker performs inference locally without network access, while tool results are included in the calling agent's usual conversation.

Run the included example directly:

```sh
.build/decisions/runtime/release/BobDecision .build/decisions/model LocalDecision/example.json
```

Without the request-file argument, the worker accepts one JSON request per input line and returns one JSON response per line, keeping the model warm. An example request is in `LocalDecision/example.json`. To repeat the live GPU regression and latency probe:

```sh
BOB_CLEF_EXECUTABLE="$PWD/.build/decisions/runtime/release/BobDecision" \
BOB_CLEF_MODEL_DIRECTORY="$PWD/.build/decisions/model" \
bash scripts/test.sh --filter DecisionModelTests/testLiveClefFlash
```

Measured October 16, 2026 on an M4 Max (40 GPU cores, 64 GB RAM): eleven warmed 135-token routing decisions averaged **238 ms** (233–262 ms); a joint choice/boolean/score request with 300 tokens took **462 ms**. Initial model loading took **3.1 seconds**, followed by a **1.1-second** first decision in that run. A separate cold 254-token two-question probe reached **6.73 GiB peak macOS physical footprint**. These are short correctness probes, not an accuracy benchmark or a latency guarantee for larger states. The native regression run passed 111 selected tests including live inference; the separate desktop capture test was excluded because its fixture window was covered.

## Tool risk scoring

Every agent tool call is scored locally by Clef before its handler can run, including file reads and writes, shell commands, browser and desktop tools, workspace tabs, and `local_decide`. Clef receives one choice question: intrinsic risk is `low`, `medium`, `high` or `critical`. It does not score authorization, classify concerns, choose allow/deny, or recommend approval.

Bob derives execution from the risk alone: low and medium run automatically; high and critical ask for human confirmation, regardless of model confidence. The risk, probabilities, timing, input digest and resulting execution route are recorded in the durable turn journal before execution. Expanded activity shows the risk score. Historical review records remain readable. File conflict checks, current-target checks and app access remain in effect. Shell commands execute directly on the Mac with the user's normal file permissions and network access.

The guidance adapts [Codex's public intrinsic-risk taxonomy](https://github.com/openai/codex/tree/e7de1f444089c29ac002e3df08d940f6de8a2613/codex-rs/prompts/templates/guardian), pinned at `e7de1f444089c29ac002e3df08d940f6de8a2613`. Upstream source, license and adaptation provenance remain bundled for attribution. Bob uses its own local scoring gate and does not claim Codex model quality or behavioral parity.

Scoring receives complete I/O-bearing arguments, original user requests kept separately from model compaction summaries, recent untrusted evidence, and current control descriptions for browser or desktop actions. The offline `local_decide` tool is scored by its verified inert execution contract, payload size, question count, token limit and full-argument SHA-256; dangerous commands in its text cannot execute. Quoted files, pages, tools and assistant output cannot change the scorer's instructions.

Missing weights/runtime, malformed responses, oversized actions and a 30-second scoring deadline block execution. Supplemental history is capped at 8 KiB and marked when shortened. Tokenizer overflow automatically retries with 2 KiB, then no supplemental history, under the same deadline; the exact action, target and original user instructions stay unchanged. The final input is limited to 96 KB and 8192 encoded tokens. Clef's allocator cache is capped at 256 MiB. Cancellation stops inference before execution.

Run model-free checks with `bash scripts/test.sh --filter ToolSafetyTests`. With `BOB_CLEF_EXECUTABLE` and `BOB_CLEF_MODEL_DIRECTORY` set as above, `ToolSafetyTests/testLiveClefReviewsDangerousCalls` tests benign and hazardous risk categories without executing the examples. These probes are limited examples, not a calibrated accuracy guarantee.

## Local browser navigation

The main model is instructed to prefer `browser_delegate` for page navigation. It supplies a specific goal, a starting URL (or an empty string for the current page), any exact labeled text inputs, and a step limit. Clef then selects successive actions from fresh WebKit snapshots locally, returning the final page and a trace to the main model for verification. Individual browser tools remain available for recovery and work outside navigation. Clef shares the existing worker and weights with the safety reviewer.

The native controller offers observed HTTP/HTTPS links, buttons, approved text inputs, scrolling, completion, and handoff. Link navigation opens the observed URL directly without executing a link's JavaScript handler. Button clicks and text entry use the existing browser tools and risk-based approvals. Clef cannot generate a URL, script, or new form text. Protected fields remain unavailable. Every delegated browser call, including the initial read/open, goes through the same blocking safety review and permission boundary as a main-model call. The delegation's stated goal cannot grant user authorization.

Delegation defaults to six calls and permits at most twelve, including the initial read/open. Low confidence, malformed or unavailable inference, stale targets, repeated actions, missing information, declined confirmation and failed risk scoring return control or stop the run. Stop Agent cancels local inference and browser loading. The chooser considers up to 32 observed actions, ranked against the goal, plus completion and handoff; page text used for selection is an explicitly marked excerpt. Exact execution arguments are still reviewed in full. Final results indicate any page truncation and direct the main model to obtain fresh state before acting on omitted content.

Each child call appears in tool activity with its review and is synchronized to the turn journal before execution. Recovery retains completed steps and marks interrupted actions as uncertain; it never replays them. Delegated calls stay inside the parent tool result in model history, so they do not create invalid nested API tool messages.

On the same M4 Max, Clef selected two button hops and completion in a native, isolated three-page WebKit fixture with **0.56–1.81 second** decisions across two runs (345–357 input tokens). There were no main-model calls during delegation. The cold end-to-end route took **21–34 seconds**, including model loading, all four tool reviews, and automatically accepted fixture approvals. This verifies the local handoff, not a general web navigation accuracy benchmark or a claim that full browsing takes less than a second. Required safety reviews still dominate this example's elapsed time. The regression run passed 144 selected tests, including live navigation and the safety probes; the unrelated native desktop capture fixture was excluded. Run `BrowserNavigationTests` with the Clef environment variables above for the live probe.

## Initial shell

- One native window per project, with its own session sidebar, chat composer, editor, terminal, Git state, and agent runs. Reopening a project focuses its existing window. Connections are shared across project windows.
- Light and dark palettes follow macOS appearance automatically, including the editor and terminal. Neutral surfaces, compact navigation, and a restrained indigo accent keep the interface quiet.
- A single-line composer floats above the chat as a native Liquid Glass capsule on macOS 26, with 16-point outer spacing and a circular Send control on the right. Conversation content scrolls behind the glass, with space reserved for the latest message and any approval card. Earlier macOS versions use a material surface; Reduce Transparency uses an opaque capsule. Return or `⌘Return` sends. New Chat preserves an already empty chat and its draft. Conversation titles stay on one line and truncate at the end. Open Project lives in the File menu (`⌘O`); Settings lives in the Bob menu (`⌘,`).
- Model and effort menus live in the indigo status bar across the bottom of the window, alongside the project, Git branch, selected chat, active work, and Usage. Activity and metrics follow only the selected chat. The unlabeled context meter opens a popover explaining the estimated fill, budget, and compaction; direct providers use Bob's default context budget, while Claude uses its reported window when available. Input **↑** and output **↓** show the chat's cumulative provider-reported token counts, including titles and compaction. Counts survive summaries and restarts, with unreported usage left unknown. Idle chats omit a “Ready” label. The model menu groups connected providers, whose catalogs are cached across windows and restarts and scoped to the account or server connection. Effort choices follow catalog capabilities or known model support, persist per chat, and use `reasoning.effort` for OpenAI Responses, `output_config.effort` for Claude API, `--effort` for Claude Code, or `reasoning_effort` for compatible endpoints. Auto leaves the provider default unchanged. Configure custom model IDs in Settings when a provider does not offer a model catalog.
- Consistent 16-point chat padding, right-aligned user bubbles, and unlabeled assistant replies. Sending uses a native spring to move the rendered bubble from the composer to its measured transcript position; the transcript bubble appears when the spring completes, with scrolling held steady during the flight. Reduce Motion skips the movement. Consecutive tool calls share a compact activity group with a live summary. Unsuccessful tool calls appear as neutral attempts with a muted dot, without failure counts or red error icons. Click any group or tool row to expand it without chevrons or elapsed times. Expand a group to inspect individual calls and their input/output; visible messages start a new group. Completed output items, final text, and refusal events are reconciled with streamed deltas; empty completed replies produce an actionable error.
- Chat, session and file lists, model settings, command results, diffs, and tool details fade at overflowing vertical edges. The fades follow the scroll position, preserve end items, adapt to both appearances, and turn off for Reduce Transparency.
- Multiple chats can run concurrently within a project. Streaming text, tool results, approvals, and Stop (`⌘.`) belong to each chat; switching chats leaves background runs active. Model and effort selection stay available in idle chats. Closing the project stops all its runs. The shared Browser and Computer panels each belong to the first run that uses them until it ends, preventing conflicting snapshots and cancellation across chats. Other runs can continue model, file, and shell work.
- Bob-owned Swift tools handle project files, reviewed writes, and shell commands running directly on the Mac. Claude subscription chats use Claude Code’s streaming agent loop and a private in-process MCP bridge exposing only these Bob tools. Native Claude Code action tools, inherited MCP servers, custom hooks, and slash commands are disabled for these sessions; no permissions-bypass flag is used. Each chat retains its own Claude Code session ID for follow-ups, including recovery from the synchronized journal. Other providers use Bob’s Swift runtime actor. The UI consumes runtime events. A tool registry, permission policy, context manager, and durable turn journal keep execution separate from rendering. Agent runs have no fixed step, turn, or tool-call cap; they continue until the model finishes, the user stops them, or an execution error occurs. Context compaction, steering, tool reviews and cancellation remain active throughout long runs.
- Each assistant response, tool start, and completed tool result is written to a synchronized per-session journal. Restart recovery retains completed results and marks unfinished operations as aborted or potentially completed; it never automatically reruns a tool. Cancellation closes pending approvals and preserves the completed part of a tool batch.
- Approval responses are bound to a run, tool call, and single-use request ID. File writes compare explicit prior state, including a file's absence, and reject files created or changed while approval was pending. Read failures do not grant overwrite permission.
- Root `AGENTS.md` instructions are injected before inference. File tools discover applicable nested instructions; writes wait for newly discovered instructions to reach the model. Compaction invalidates that delivery state so directory instructions are presented again when needed.
- Context uses a default budget of 300,000 estimated input tokens, supplemented by provider usage when available. Near the budget, the model summarizes older work while retaining the latest user prompt and recent complete tool groups. This is a local budget, not a guarantee of a provider's model limits; oversized prompts produce an actionable error.
- Transient HTTP and connection failures retry at most twice with exponential backoff and `Retry-After` support. Authentication and known quota errors fail immediately. Once response text has been displayed, failures are surfaced without replaying that text. Backoff is cancellable; server deadlines over 60 seconds are surfaced instead of retried early.
- Native text editor with file-aware syntax highlighting, line numbers and total line count, and horizontal scrolling without wrapping. Changed files open in a unified diff with syntax highlighting, old/new line numbers and addition/removal counts; an Edit/Diff switch keeps the full editor available. Diff syntax uses the editor's language rules and colors, with full-revision context for multiline comments and strings, while colored backgrounds and gutter markers identify additions and removals. Comparisons include staged and unstaged changes against HEAD, new files, renamed files, deleted files, and unsaved buffers. Outside Git repositories, retained Bob checkpoints provide the original text. Refresh updates clean buffers while preserving unsaved edits. Includes local undo, explicit save, and protection against overwriting an externally changed file.
- An indented file tree expands folders inline, loads their children on demand, and preserves expanded branches across chats, tabs, and refreshes. Changed files have colored status badges; parent folders indicate changes inside them. Deleted files and their missing parent folders stay in the tree so their diffs can be opened.
- Use **+** in the Files header to create a file or folder at the project root, or right-click a tree item to create a sibling/child, rename it, or move it to Trash. New files open in the editor. Renaming updates open file paths and preserves unsaved buffers and expanded folders. Moving an item to Trash requires confirmation and blocks if any affected tab has unsaved changes; clean affected tabs close, and the item can be restored in Finder. Name collisions never replace existing items, and symlinks are renamed or trashed as links.
- Git diff and status inspection, and a code-review prompt.
- An always-visible agent chat and a resizable right sidebar that starts with Editor open. Use **+** inside the sidebar or the Workspace menu to open Editor, Plan (`⌘⌥6`), Changes, Terminal, Browser, Computer, or Simulator (`⌘⌥5`). Selecting a file replaces the current editor tab when it has no unsaved edits; edited files keep their own tabs and buffers. Reopening a file selects its existing tab. Close buttons and `⌘W` close tabs, with unsaved edits protected. Closing the last file returns its tab to an empty Editor, which stays open without a close button. Closing Browser releases its WebView; closing Terminal stops its shell.
- Plan displays selectable Markdown with headings, lists, checklists, quotes, code blocks, links, and tables. The AI reads and writes detailed plans through `workspace_read_plan` and `workspace_update_plan`. Plans persist with their chat across restarts; closing the tab preserves the document, and background updates stay with the originating chat. Use Copy Markdown to copy the source.
- The agent can list, open, select, and close tabs through `workspace_tabs`, `workspace_open_tab`, `workspace_select_tab`, and `workspace_close_tab`. Browser and computer tools reveal their tab automatically. Agent tab controls preserve unsaved files and cannot close a running terminal. Open tabs and buffers survive chat changes and panel switches within the project window.
- The Simulator tab runs an iPhone or iPad inside Bob using Xcode's CoreSimulator device and live IOSurface framebuffer. Choose a device and press Start; click to tap, drag to swipe, and type while the display has focus. Command shortcuts continue to control Bob. Home and **… → Install App…** are in the tab toolbar; installation requires an iOS Simulator `.app` build. Closing or hiding the tab detaches the display while leaving the shared device running. Use **… → Shut Down Device** to stop it explicitly. No Screen Recording or Accessibility permission is needed for this tab. The bridge uses private Xcode interfaces and currently supports Xcode 26; other versions fail with an actionable error. Keyboard input uses a US physical key map; IME composition, pinch gestures, and display rotation are not yet supported. Attribution is packaged in `Simulator-NOTICE` and `Simulator-LICENSE`.
- A native WebKit browser with an address bar, back/forward, reload/stop, and agent tools for navigation, page reading, scrolling, clicking, and filling text fields. Each project creates its own private browser session on first use; cookies stay in memory and are discarded when its window closes. The browser does not import Safari or Chrome sessions.
- Native desktop tools list/open apps, capture an approved window, inspect accessibility controls, click, replace text, press keys, scroll, and drag. ScreenCaptureKit captures individual windows; Accessibility performs direct control actions where supported. Core Graphics event fallbacks raise the approved app and target its process, checking window identity, geometry, focus, and occlusion before input. No JavaScript/Python runtime or external agent CLI is used.
- A command center (`⌘K`) searches commands and files in the current project; `⌘P` opens its file finder directly. Filter with All, Files, or Commands, or cycle filters with Tab/Shift-Tab. Use ↑/↓ to select, Return to run a command or open a file in the editor, and Escape to close. Filename and path search supports abbreviations and includes nested, hidden, and untracked files while skipping Git metadata, dependency folders, and build caches. The project builds a prepared filename index in the background, reuses it across palette openings, and updates affected paths through native filesystem events. Searches retain at most 20 file results; lost events trigger a full refresh. Opening a file reuses its existing tab and preserves unsaved buffers.
- A basic PTY terminal (`⌘J`), native menus, and keyboard shortcuts. `⌘⌥1` opens Editor, `⌘⌥2` opens Changes, `⌘⌥3` opens Browser, and `⌘⌥4` opens Computer. `⌘J` opens or selects the terminal tab while keeping the sidebar visible.
- Persisted file checkpoints with conflict-aware undo for Bob's editor and `write_file` tool. Up to 20 checkpoints or 20 MB are retained per project.

All tool calls run automatically when Clef scores them as low or medium risk. High and critical scores require human confirmation; there is no separate model approval or denial decision. Failed scoring blocks execution. File tools stay within the selected project, reject symlink escapes and Git metadata access, and limit text files to 2 MB. Agent shell commands run directly through `/bin/zsh -f -c` on the Mac, starting in the selected project directory. They use the user's real home directory, normal temporary directory, installed tool path, file permissions and network access, with no workspace sandbox or separate network grant. Commands receive a filtered environment without inherited provider credentials or shell startup hooks. Their changes are not covered by file checkpoints. Command output is bounded, and commands have a 60-second limit. The user's interactive terminal remains independent of agent command execution.

Browser clicks and typing assessed as high or critical risk require approval showing the page and target control. Browser tools use main-frame DOM snapshots and reject stale references; password, payment, and authentication-code fields require manual interaction. Page contents are untrusted input. Cross-frame browser automation remains future work.

## Computer use

Open **Workspace > Show Computer** (`⌘⌥4`), enable Computer use, and grant Bob **Screen Recording** and **Accessibility** using the permission controls. macOS may require reopening Bob after granting access. Select a vision-capable model, then ask the agent to use a named app. The Computer panel can also capture an app window manually. Captures expose the app's other window IDs so the agent can select an exact window.

App access assessed as high or critical risk is requested before agent capture or app launch. Low- and medium-risk access is granted for the current run after computer use is enabled. **Allow once** grants access for that run; **Always allow app** saves the bundle ID. Remove saved grants in the Computer panel. Desktop actions assessed as high or critical risk get their own approval showing the app, window, target, and proposed input. Revocation or disabling computer use invalidates snapshots and interrupts pending operations across project windows. The existing Stop Agent command cancels capture and control; detected local input interrupts foreground event sequences and stops the agent.

Each action consumes its snapshot. New screenshots and control references are returned to the model after actions; stale references, changed window geometry, app restarts, changed text fields, protected controls, and covered coordinate targets are rejected. Coordinates are mapped from screenshot pixels into macOS screen points, including Retina scaling and negative display origins. Direct accessibility actions can work in the background; mouse, scrolling, drag, and keyboard fallbacks may bring the target app forward.

Known password, authentication-code, and payment controls are excluded from text extraction and redacted in screenshots. Terminal apps, Bob, ChatGPT/Codex, Keychain Access, and system security/permission apps require manual interaction. The agent cannot approve macOS permission dialogs. Desktop changes are outside file checkpoints. Locked use, automatic unlocking, and arbitrary script execution inside desktop tools are not implemented.

Screenshots are sent as image content through Responses, Anthropic Messages, or compatible Chat Completions. Only the two newest frames remain in active model history; screenshot-heavy turn journals checkpoint after 8 MB. Saved screenshots are covered by the same private-file permissions as conversations. Context compaction invalidates computer references so the agent must observe again.

The design follows [Codex's public per-app access configuration](https://github.com/openai/codex/blob/6b991972c5b539198dcea9bac4fc14e57559c3af/codex-rs/config/src/computer_use.rs), the [documented Computer Use workflow](https://learn.chatgpt.com/docs/computer-use), and [OpenAI's custom UI-tool integration](https://developers.openai.com/api/docs/guides/tools-computer-use-integration#use-your-own-ui-tools). Bob provides its own Swift implementation; this does not claim parity with the separately shipped Codex Computer Use plugin.

Native integration tests build an isolated AppKit fixture and exercise capture and input only when the test host exposes both macOS permissions and valid remote `AXWindow` geometry. This development host reports the permission flags but does not expose that geometry, so the native capture/input probe is explicitly skipped. Live desktop control remains unverified here; protocol, approvals, cancellation, redaction, coordinate mapping, persistence, and image serialization have automated coverage.

The terminal currently supports basic shell interaction and bounded scrollback, not a full VT terminal emulator. LSP, staging and commits in the UI, PR integration, and hardened runtime/notarization are future work. Saved conversations resume with their journaled tool history; interrupted model output is displayed but is not treated as a completed assistant turn. An interrupted command may have changed files before cancellation or a crash; recovery records that uncertainty instead of assuming the command did nothing.

## Structure

- `Sources/BobCore`: runtime actor, turn journal and history repair, tool registry, instructions and context management, model adapters, retries, permission policy, file/checkpoint services, process execution, and Git operations.
- `Sources/Bob/AgentHarness.swift`: native UI event adapter, backend selection, cancellation ownership, and request-scoped approvals.
- `Sources/BobCore/ClaudeCodeRuntime.swift`: official Claude Code stream/control protocol and reviewed Bob MCP tools.
- `Sources/Bob/ClaudeCodeConnection.swift`: subscription connection, official sign-in, and runtime model discovery.
- `Sources/Bob/AgentTools.swift`: project, browser, and desktop tool implementations.
- `Sources/Bob/ComputerSession.swift`, `NativeComputerDriver.swift`, `MacAccessibility.swift`: app access, project-scoped desktop sessions, window capture, accessibility references, and native input.
- `Sources/Bob/Authentication.swift`: Keychain storage and ChatGPT OAuth.
- `Sources/Bob`: project-scoped SwiftUI windows and AppKit editor/terminal views.
- `Tests/BobCoreTests`: streaming and retries, approval isolation, interrupted batch recovery, instruction delivery, context budgets, project file boundaries, host shell execution, local server access, tmux sessions, undo conflicts, and process cancellation.

The app's source of truth is [GOAL.md](../GOAL.md).
